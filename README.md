- сервис управления email-рассылками;

- систему ролей и прав доступа;
- кеширование через Redis;
- статистику рассылок;
- автоматическое тестирование и контроль качества кода.

## Кеширование и Redis
В проекте используется Redis для кеширования:
- кеширование детальной страницы продукта
- низкоуровневое кеширование списка продуктов по категории
- кеширование dashboard-статистики сервиса рассылок
- автоматическая очистка кеша рассылок после создания, изменения, удаления, отправки и отключения рассылок
- TTL кеша продуктов — 15 минут
- TTL кеша статистики рассылок — 5 минут

- `/blogs/delete/<id>/` — удаление статьи

## Сервис рассылок
Доступные страницы сервиса рассылок:
- `/mailing/` — dashboard сервиса рассылок
- `/mailing/recipients/` — список получателей
- `/mailing/recipients/create/` — создание получателя
- `/mailing/messages/` — список сообщений
- `/mailing/messages/create/` — создание сообщения
- `/mailing/mailings/` — список рассылок
- `/mailing/mailings/create/` — создание рассылки
- `/mailing/mailings/<id>/` — детальная страница рассылки

### Модели сервиса рассылок
- `Recipient` — получатель рассылки: email, Ф. И. О., комментарий, владелец
- `Message` — сообщение рассылки: тема письма, тело письма, владелец
- `Mailing` — рассылка: время начала, время окончания, статус, сообщение, получатели, владелец
- `Attempt` — попытка отправки: время попытки, статус, ответ сервера, рассылка

### Статусы рассылки
Статус рассылки пересчитывается динамически:
- `Создана` — текущее время раньше начала рассылки
- `Запущена` — текущее время находится между началом и окончанием рассылки
- `Завершена` — текущее время позже окончания рассылки

### Отправка рассылки
Рассылку можно запустить вручную через интерфейс. При запуске проверяется, что текущее время находится между временем начала и окончания рассылки. Для каждого получателя выполняется отправка письма через `send_mail()`. Результаты отправки сохраняются в `Attempt` через batch-создание.

## Права доступа и модерация
Реализована система ролей и разграничения доступа:

### Модератор продуктов
Пользователь группы «Модератор продуктов» может:
- одобрять продукты
- отклонять продукты
- оставлять комментарий модератора
- снимать продукты с публикации
- удалять продукты


### Контент-менеджер
Пользователь группы «Контент-менеджер» может:
- создавать статьи
- редактировать статьи
- удалять статьи

### Менеджер рассылок
Пользователь группы «Менеджер рассылок» может:
- просматривать все рассылки
- просматривать всех получателей рассылки
- просматривать список пользователей сервиса
- блокировать и разблокировать пользователей сервиса
- отключать рассылки

Менеджер рассылок не может редактировать или удалять чужие рассылки и чужих получателей.

### Владельцы продуктов
- продукт автоматически привязывается к автору
- только владелец может редактировать свой продукт, если продукт не опубликован
- удалить продукт может владелец или модератор

### Статусы товаров
Товары поддерживают несколько статусов:
- черновик
- на проверке
- опубликован
- отклонен

## Пользователи и безопасность
В проекте реализована кастомная модель пользователя с авторизацией по email.

Реализовано:
- регистрация пользователя
- подтверждение email по ссылке из письма
- вход в систему
- выход из системы
- редактирование профиля
- восстановление пароля через email
- блокировка и разблокировка пользователей менеджером рассылок

Возможности пользователей:
- регистрация на сайте
- подтверждение email по ссылке из письма
- вход по email и паролю
- выход из аккаунта
- редактирование профиля
- восстановление пароля через email

Новый пользователь после регистрации создается неактивным. После перехода по ссылке подтверждения email пользователь активируется и может войти в систему.
